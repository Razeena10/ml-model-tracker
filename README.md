# ml-model-tracker

A reproducible binary-classification pipeline built with **scikit-learn** and
tracked with **MLflow**, with a complete automated test suite. Built as a
portfolio project for ML Engineer and MLOps roles.

---

## Learning objectives

- Train a baseline classifier end-to-end on a trusted, built-in dataset.
- Guarantee **reproducibility**: fixed seeds, stratified splits, pinned
  dependency versions, and automated tests that enforce all of these.
- Track parameters, metrics, and the trained model with **MLflow** so
  experiments are auditable and comparable instead of lost in terminal output.
- Report evaluation metrics clearly for **both** clinically relevant
  positive-class definitions — not just the scikit-learn default.
- Practice engineering hygiene: modular code, CWD-independent paths, clean
  `.gitignore`, and honest documentation.

## Architecture and workflow

```
             ┌──────────────────────────────────────────────────────┐
  data ───▶  │ src/data_loader.py  load + validate (569×30, 0 NaNs) │
             └──────────────┬───────────────────────────────────────┘
                            ▼
             ┌──────────────────────────────────────────────────────┐
             │ train.py  stratified split (80/20, seed=42)          │
             │   Pipeline: StandardScaler → LogisticRegression      │
             │   .fit() on TRAINING data only                       │
             └──────────────┬───────────────────────────────────────┘
                            ▼
             ┌──────────────────────────────────────────────────────┐
             │ src/evaluate.py  accuracy / two positive-class       │
             │   groups / per-class report / confusion matrix       │
             │   saved to artifacts/metrics.json                    │
             └──────────────┬───────────────────────────────────────┘
                            ▼
        ┌───────────────────┴────────────────────┐
        ▼                                        ▼
┌─────────────────────────┐        ┌──────────────────────────────┐
│ src/tracking.py (MLflow)│        │ artifacts/model.joblib       │
│  params, metrics, model │        │   consumed by predict.py     │
│  → absolute SQLite path │        │   (loads & predicts, no fit) │
│  → absolute mlartifacts │        └──────────────────────────────┘
└─────────────────────────┘
```

The test set is held out from every fitting step. Preprocessing lives inside
the sklearn `Pipeline` so the scaler is only ever fitted on training data.

## Usage — exact commands

All commands assume the virtual environment is active and your working
directory is the project root.

### Train, evaluate, and track

```powershell
python train.py
```

This single command:
1. Loads the dataset and splits it 80/20 (stratified, `random_state=42`).
2. Fits `StandardScaler → LogisticRegression(max_iter=1000)` on training data only.
3. Evaluates on the held-out 114-sample test set.
4. Saves `artifacts/metrics.json` and `artifacts/model.joblib`.
5. Checks that the reloaded model produces identical predictions to the in-memory model.
6. Logs a complete MLflow run: parameters, metrics, model artifact, and tags.

### Predict from a saved model

```powershell
python predict.py
```

Loads `artifacts/model.joblib` and scores 3 sample rows. Never retrains.

### Run the automated test suite

```powershell
pytest -v
```

Expected result: **83 passed, 2 warnings** (warnings originate in MLflow's
own library code; no action needed). See [Test results](#test-results).

### Open the MLflow UI

The tracking URI is printed at the end of each `python train.py` run.

```powershell
mlflow ui --backend-store-uri <TRACKING_URI_printed_by_train.py>
# → open http://127.0.0.1:5000
```

The default TRACKING_URI is the **absolute path** to `mlflow.db` in the
project root (see [MLflow tracking details](#mlflow-tracking-details) below).

## Evaluation results

From a verified run of `python train.py` (held-out test set, 114 samples).
These values are also saved in `artifacts/metrics.json` and are reproduced
identically on every run due to the fixed seed.

### Global metric

| Metric | Value |
|---|---|
| Accuracy | 0.9825 (112 / 114 correct) |

### Benign-positive group (positive class = 1 = benign)

Describes how well the model detects benign cases.
This is scikit-learn's default positive class for this dataset.

| Metric | Value | Interpretation |
|---|---|---|
| Precision | 0.9861 | Of cases predicted benign, 98.61% truly were |
| Recall | 0.9861 | Of truly benign cases, 98.61% were correctly identified |
| F1-score | 0.9861 | Harmonic mean of benign precision and recall |
| Support | 72 | True benign cases in the test set |

### Malignant-positive group (positive class = 0 = malignant)

Describes how well the model detects malignant cases — the clinically
important error direction. A miss here means a malignancy is called benign.

| Metric | Value | Interpretation |
|---|---|---|
| Precision | 0.9762 | Of cases predicted malignant, 97.62% truly were |
| Recall | 0.9762 | Of truly malignant cases, 97.62% were correctly identified |
| F1-score | 0.9762 | Harmonic mean of malignant precision and recall |
| Support | 42 | True malignant cases in the test set |

**Why report both?** A single "benign-positive" view hides malignancy-detection
performance. The two groups differ here (0.9861 vs 0.9762), so reporting only
one would be misleading. Misclassifying a malignancy as benign is the more
dangerous error in a screening context; that is what the malignant-positive
group measures.

### Confusion matrix

Rows = true class, columns = predicted class, order `[malignant, benign]`:

```
                 malignant   benign
  malignant           41        1     ← 1 malignancy called benign
  benign               1       71     ← 1 benign case called malignant
```

2 total errors out of 114 test samples — one in each direction.

> artifact**, not a medical device. See [Responsible use](#responsible-use).

## MLflow tracking details

### How paths are resolved

`src/tracking.py` derives the tracking URI and artifact location at
**import time** from the absolute path of the source file:

```python
_PROJECT_ROOT = Path(__file__).resolve().parent.parent  # src/ → project root
TRACKING_URI   = "sqlite:///" + (_PROJECT_ROOT / "mlflow.db").as_posix()
ARTIFACT_LOCATION = (_PROJECT_ROOT / "mlartifacts").as_posix()
```

This means both paths are **absolute** and **CWD-independent** — `python train.py`
works correctly from any directory. It also avoids a hang that occurred when
the project lived under OneDrive: a relative `sqlite:///mlflow.db` URI caused
MLflow to write model artifacts into an OneDrive-synced `mlruns/` directory,
which OneDrive locked during sync. Using absolute paths and an explicit
`artifact_location` routes artifacts to `mlartifacts/` instead.

### Environment-variable overrides

All three values can be overridden without changing source code:

| Variable | Controls | Default |
|---|---|---|
| `MLFLOW_TRACKING_URI` | SQLite database path (full URI) | `sqlite:///<project_root>/mlflow.db` |
| `MLFLOW_ARTIFACT_LOCATION` | Directory for model artifacts | `<project_root>/mlartifacts` |
| `MLFLOW_EXPERIMENT_NAME` | Experiment name in the UI | `breast-cancer-classification` |

**Windows — PowerShell (isolated run, e.g. outside OneDrive):**

```powershell
$env:MLFLOW_TRACKING_URI      = "sqlite:///C:/temp/ml_isolated.db"
$env:MLFLOW_ARTIFACT_LOCATION = "C:/temp/ml_mlartifacts"
python train.py
```

**Windows — Command Prompt:**

```cmd
set MLFLOW_TRACKING_URI=sqlite:///C:/temp/ml_isolated.db
set MLFLOW_ARTIFACT_LOCATION=C:/temp/ml_mlartifacts
python train.py
```

> The isolated-store workflow was verified end-to-end: the run reached
> `FINISHED`, all parameters and scalar metrics were recorded, and the
> `MLmodel` artifact was written under the isolated store.

### What is tracked

Each `python train.py` call creates one MLflow run containing:

| Type | Key | Value |
|---|---|---|
| Parameter | `algorithm` | `LogisticRegression` |
| Parameter | `scaler` | `StandardScaler` |
| Parameter | `random_state` | `42` |
| Parameter | `test_size` | `0.2` |
| Parameter | `max_iter` | `1000` |
| Metric | `accuracy` | 0.9825 |
| Metric | `precision` | 0.9861 (benign-positive, default) |
| Metric | `recall` | 0.9861 (benign-positive, default) |
| Metric | `f1` | 0.9861 (benign-positive, default) |
| Tag | `dataset` | `sklearn.datasets.load_breast_cancer …` |
| Tag | `sklearn_version` | `1.9.1` |
| Artifact | `model/` | Fitted sklearn Pipeline (logged via `mlflow.sklearn`) |

Only the four scalar metrics are logged to MLflow. The full two-group
evaluation (including the malignant-positive metrics and the confusion matrix)
is saved to `artifacts/metrics.json`.

### MLflow concepts

- **Experiment** — a named collection of runs. This project uses `breast-cancer-classification` by default.
- **Run** — one execution of the training pipeline, with a unique run ID.
- **Parameter** — an input you chose (algorithm, seed, test size).
- **Metric** — an output you measured (accuracy, F1).
- **Artifact** — a file the run produced (the saved sklearn Pipeline, logged with `mlflow.sklearn.log_model`).

### Known limitation — default tracking store under OneDrive

The project-default `mlflow.db` + `mlartifacts/` have not been retested with
the stale `mlflow ui` server processes that were previously running (ports 5000
and 5001). The hang was definitively traced to OneDrive file-sync locking the
relative `mlruns/` artifact directory when multiple `mlflow ui` processes held
handles to `mlflow.db`. The fix (absolute URI + explicit `artifact_location`)
prevents that specific failure path, but the project-default store has not been
verified while those servers remain running. Use the env-var override above if
you encounter a hang.

## Model serialisation

The fitted pipeline is saved to `artifacts/model.joblib` using joblib.
`predict.py` loads it and predicts — it never retrains.

Both paths are resolved **absolutely** (relative to the project-root file's
location), so they work correctly regardless of the current working directory.

**Security note:** `joblib` uses Python's `pickle` machinery. Loading a
`.joblib` file can execute arbitrary code. Only load model files you trained
yourself or from sources you fully trust.

**Compatibility note:** Pickled models record the library versions they were
created with. Loading with a different scikit-learn version (especially an
older one) may fail or behave unexpectedly. The pinned versions in
`requirements.txt` (scikit-learn 1.9.1) match the saved model.

## Reproducibility

- Fixed `random_state=42` and stratified splitting produce identical splits on every run.
- `LogisticRegression` on this data is deterministic — repeated fits with the same seed produce byte-identical predictions and metrics.
- Dependency versions are pinned in `requirements.txt`.
- The test suite enforces all of these: two independent full training cycles produce identical metrics (`test_repeat_full_training_cycle_gives_identical_metrics`).

## Limitations

- A single baseline model (LogisticRegression) with default hyperparameters; no cross-validation or hyperparameter search.
- Evaluation on a single 20% hold-out split; 114 test samples carry noticeable statistical uncertainty.
- The MLflow UI is not an automated test target; server startup and HTTP endpoints are not tested.
- `train.main()` as a single integrated call is not in the pytest suite; the full workflow was verified via a standalone isolated-store script.
- The project-default tracking store has not been re-verified while legacy `mlflow ui` server processes remain running on the host.

---

## Responsible use

This project is a **teaching artifact, not a medical device**. It must never
be used to inform real clinical decisions. The dataset contains no patient
identifiers, and nothing sensitive is logged to MLflow. The confusion matrix
shows 1 missed malignancy (false negative) in 114 test samples; in a clinical
screening context that error rate would require extensive further validation
before any deployment.
